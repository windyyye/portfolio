# 002. Creative layer: illustrated CSS craft, near-zero motion

- **Status:** Accepted
- **Date:** 2026-10-01

## Context

Issue #21 reframes the site from a client-facing portfolio into a personal career diary.
The framework and hosting question is closed by ADR 001 (Astro, Firebase Hosting); this
record decides the **creative layer** — how the site looks, moves, and illustrates itself —
which issue #21 required deciding before implementation ("determine the technology stack
beforehand").

The decision is grounded in the archetype-sweep research (`docs/research/revamp-inspiration.md`),
whose extracted constraints are: a cohesive illustrated system is wanted (Maggie Appleton's
site was the sweep's only unconditional positive); book-style craft and structure are wanted
(Lynn Fisher); color and playful energy are wanted but hard-outlined chunkiness is not
(neo-brutalism was initially loved, then rejected as eye-straining); humor is a recurring
positive. Hard constraints: a $0 budget, near-zero motion, and content-first scope.

## Decision

Keep Astro; the creative layer is **CSS craft plus hand-drawn or programmatic illustration,
with near-zero motion**:

- All visual work is done in CSS (layout, texture, color, type) and SVG illustration drawn
  by Windy or generated by committed programmatic render scripts, per the DESIGN.md imagery
  rules. Illustrations are committed to the repository.
- Motion is limited to small CSS transitions (hover states, focus states). No animation
  libraries, no WebGL or canvas frameworks, no scroll-driven effects.
- No paid assets, services, or APIs; the site remains fully static on free tiers.
- Astro islands remain available if a single page ever warrants a contained experiment,
  without changing the site-wide approach.

## Alternatives considered

- **Framework migration (SvelteKit, Next, etc.):** rejected. The learning budget is better
  spent on illustration and design — the actual point of #21 — and static output + Markdown
  remains the right fit for a diary. ADR 001 stays valid.
- **WebGL / canvas playground (Bruno Simon style):** rejected. Directly against the recorded
  motion aversion and budget constraint, and it displaces diary content with spectacle.
- **Motion libraries (GSAP and similar):** rejected. The constraint is near-zero motion by
  taste, not by capability.
- **Neo-brutalist CSS system (hard borders, offset shadows, neon):** rejected. The energy was
  liked, but the execution was judged eye-straining; color must live softly inside a cohesive
  system instead of in loud frames.
- **Terminal / single-gimmick concepts:** rejected as gimmicks that age badly and fight
  readability for long-form diary entries.

## Consequences

Design effort concentrates on illustration, typography, color, and structure — the areas the
research identified — rather than on rendering technology. Pages stay fast and accessible by
construction; the Lighthouse 90+ target is realistic. Cost stays at zero. The main burden
moves to producing a steady supply of illustrations (hand-drawn or programmatic), which is a
content workload, not a technical dependency. If a future page genuinely needs richer
interaction, an Astro island can host it without revisiting this decision.
